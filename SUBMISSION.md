## Project description

PulseRun is a pay-per-run compute and CI runner protocol built on Stellar and
Soroban. Compute work is metered and bursty but usually paid for retroactively,
which is why 27% of cloud spend is wasted on idle or over-provisioned resources
(Flexera, _State of the Cloud 2025_) and 83% of container cost is tied up in idle
resources (Datadog). PulseRun inverts the payment model: a requester locks a
budget in a Soroban escrow before a job starts, a runner executes the job and
submits a metered execution proof, and the contract settles for the seconds
actually executed while returning the unspent remainder. The escrow enforces the
terms on both sides — the runner is funded before running, the requester can
never be billed past their ceiling, and either party can freeze a suspicious
proof inside a dispute window. This repository is the application layer; the
contracts live in `pulserun-core`.

## Repository relationship

The project is split into two repositories so each concern can be reviewed and
supported independently:

- **`pulserun-core`** — the Soroban contracts. `PulseEscrow` holds and settles
  funds; `mock_token` exists only to exercise settlement in tests. A pure Rust
  workspace with no application code.
- **`pulserun-client`** (this repo) — the application layer. A TypeScript
  workspace with the `pulserun` requester CLI and the `pulserun-daemon` runner.

How they connect technically: the client builds and signs Soroban transactions
against the deployed `PulseEscrow` id, using the escrow's published error codes
and `ComputeJob`/`ExecutionProof` types restated in `packages/cli/src/client/soroban.ts`
and `packages/daemon/src/contract.ts`. Contract ids are passed at runtime through
environment variables (`PULSEESCROW_ID`, `MOCKTOKEN_ID`) — see pulserun-core's
deployment record for the source of truth. The daemon reconciles job state from
`get_job` polling; contract events are a planned pulserun-core change.

The backlog is generated by [`scripts/create-issues.sh`](scripts/create-issues.sh),

## Planned issues

### CLI

- **feat(cli): add a signer abstraction so keys need not be raw S... env vars** (high) — a secret seed in the environment is the biggest key-management gap.
- **feat(cli): add `pulserun jobs` to list jobs by requester or runner** (medium) — makes job history discoverable.
- **feat(cli): dry-run create_job and print the simulated result before signing** (medium) — check amounts and addresses safely.
- **feat(cli): add `pulserun config` to show resolved network, contract and token** (trivial) — debuggable configuration.

### Daemon

- **feat(daemon): fetch job specs from a remote store to close the job-spec gap** (high) — removes the shared-filesystem requirement.
- **feat(daemon): persist the discovery high-water mark across restarts** (medium) — avoids rescanning on restart.
- **fix(daemon): back off on repeated RPC failures instead of hot-looping** (medium) — resilient to outages.
- **feat(daemon): emit structured JSON logs with job context** (trivial) — operable at scale.

### Testing

- **test(cli): cover the error-code mapping for every ABI variant** (medium) — the ABI table is part of the interface.
- **test(daemon): property test that a local failure never submits a proof** (high) — the core safety property.

### Docs and CI

- **ci: publish coverage and fail under a threshold** (trivial) — guards test depth.
- **ci: add a dependency and license audit job** (trivial) — supply-chain gate.
